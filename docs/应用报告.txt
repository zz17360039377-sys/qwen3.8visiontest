【应用案例】Qwen3.8-27B 视觉标注实测：本地多模态大模型在 CV 数据管线中的三个角色

  │ 在 RoboMaster 真实 CV 数据集 和部分网络图片（1955 张、22
  │    套、6 种标注类型）上， 我们证明 Qwen3.8-27B
  │    通过提示词配置可以承担数据管线的三类工作——批量分类复核 （一致率
  │    99.7%）、清晰目标检测预标注（IoU
  │    0.918）、数据集中文描述自动生成—— 并给出它不能做什么的量化边界（小
  │    目标定位、像素级关键点）。全部代码、提示词与 复现脚本开源。

1. 核心结论（30 秒版）

如果你只想带走三件事，就是下面这三条——每一条都有实验数据支撑，正文会展开：

  #：1
  结论：分类数据复核可以放心交给它——前提是在提示词里附上每类的参考图（few-sho
     t）。最优配置下 700 张复核只有 1 张和人工不一致，而且那 1
     张还是数据集本身标错了、模型纠正的
  数字：一致率 99.7%；没加参考图时只有 93.7%

  #：2
  结论：清晰大目标的检测预标注接近人工水平——20
     张灯条图的检出框与人工标注框几乎完全重合
  数字：Precision / Recall 均 100%，平均 IoU 0.918

  #：3
  结论：所有涉及坐标的任务，提示词里必须写明图片的像素尺寸——只补上这一句话，同一张图
     同一个提示词，框的 IoU 从 0.000（完全错位）升到 0.696
  数字：本轮最重要的单条工程发现

一句话避坑版：参考图是最强杠杆；坐标任务必声明尺寸；干扰物必须逐个显式排除；自动改标阈值
   要人工核验（本实验定为 0.95）；小目标（< 画面 5%）和像素级关键点直接放弃
   VLM。

  │ 名词解释：一致率 = VLM
  │    判的类别与人工标注文件夹一致的比例；IoU（交并比）= 两个框的重叠面积
  │    ÷ 合并面积，1.0 表示完全重合，0 表示毫不相干；few-shot =
  │    在提示词里附上几张已标注的示例图，让模型"照葫芦画瓢"。

工作流分三个角色实验：①
   质检员——对"文件夹=类别"的已有数据集逐张复核，与人工标签比对；②
   粗标注员——对检测/关键点任务输出结构化预测；③ 描述员——为数据集生成中文说明文
   档。每个角色使用独立的封闭数据集与评测脚本，预测与评测解耦。

3. 结果：批量分类复核——提示词配置决定一致率上限

主张：对同一批灰度切片分类任务，提示词配置（放大倍数、few-shot
   参考图、预处理）决定 VLM 复核一致率的上限——从 93.7% 到 99.7%。

六组配置（每组每类抽样 50 张、共 350 张，seed 固定；最后一组为每类 100
   张换种子复测）显示：few-shot 参考图是最大杠杆（+3.7
   个百分点），自动对比度增强再 +0.3。通俗地说：同一批图、同一个模型，只是"给不
   给参考图、要不要先增强对比度"这几个提示词层面的选择，就决定了复核结果是"十张错一
   张"还是"七百张错一张"。

完整提示词（原样，与 core/prompts.py 和
   reproduce/03_recheck_classify.sh
   一致）。系统提示词：

  │ You are a strict single-label image
  │    classifier. You look at the image and
  │    assign exactly one of the listed
  │    classes. You respond with a single
  │    valid JSON object and nothing else -
  │    no prose, no markdown, no code
  │    fences.

用户提示词（{类别清单} 按任务展开为每类一行 id i: "类名" -- 描述）：

  │ Classify the image into exactly ONE of
  │    these classes: {类别清单}  Output the
  │    single most likely class -- one label
  │    per image, no hedging. Respond with
  │    ONLY the JSON object {"label":
  │    "<class name exactly as listed>",
  │    "score": <number 0..1>}.

使用参考图时，消息里会先附上 N
   张参考图（顺序与类别清单一致），并在用户提示词开头加上这一段：

  │ The message contains {N+1} images: the
  │    first {N} are REFERENCE patterns
  │    shown in the same order as the class
  │    list above, and the LAST image is the
  │    sample to classify.

三个设计要点：① 输出钉死为只有一个 JSON 对象（label +
   score），杜绝长篇散文；②
   类别不止给名字还给文字描述，模型"看图对号入座"更容易；③
   参考图顺序与类别清单一一对应，等于把"每类长什么样"直接演示给模型看。

━━━━━━━━━━━━━━━━━━
4. 结果：few-shot 参考图特异性修复图标类

主张：基线的错误高度集中在图标类（哨兵 68%），注入参考图后特异性修复至
   98–100%。

数字类（1–4）在所有配置下均 ~100%——数字谁都能认；图标类（0=哨兵、6=前哨、
   7=基地）是唯一瓶颈：三个图案互为镜像、又拍在暗光里，人眼都要凑近分辨，模型自然容
   易张冠李戴。参考图注入后 0 类 68%→98%，6 类 92%→100%——相当
   于告诉模型"哨兵图标长这样、前哨长这样"，混淆立刻基本清零。这说明 VLM
   的图标类瓶颈是"见过样例太少"，而不是"认不出来"。

━━━━━━━━━━━━━━━━━━
5. 结果：最优配置的混淆矩阵接近对角

最优配置（×6 放大 + 参考图 + 自动对比度）下，350 张中仅 1
   张不一致（2→1，经人工核验为数据集真实错标，VLM
   纠正）。混淆矩阵几乎是一条对角线——对角线上的数字越大越好，代表"模型判断 =
   人工标注"。

对照基线配置的混淆矩阵：错误集中在 0→7（12 张，哨兵与基地图标在暗光下互混）。两图
   对比说明参考图注入修复的正是图标类混淆，而不是靠运气总分变高。

提示词配置：与第 3
   节相同；基线与最优配置的唯一差异是参考图与对比度预处理，保证因果归因。

━━━━━━━━━━━━━━━━━━
6. 结果：人工核验确定自动矫正的安全阈值

复核的价值在于"发现问题"，但要不要让机器自动改必须谨慎。55
   张分歧样本逐张人工核验（与官方图案对照）发现两个方向相反的事实：

  • VLM 抓到数据集真实错标（数字 1 被旧模型标成 2，置信度
     1.00）——证明它有真本事；
  • 基线配置下 VLM 分歧的正确率仅
     ~5%——证明盲信它、让它自动改档，会引入十倍于修正量的新错误。

据此确定：置信度 ≥ 0.95 的分歧自动改档，其余进入网页审查队列。0.8
   为什么不行？因为图标类存在"高置信但错误"的分歧，0.8
   的阈值会被它们穿透；0.95
   以上基本只剩"数字类真错标"这种高置信修正。规则简单，但这个数是 55
   张人工核验标定出来的。

━━━━━━━━━━━━━━━━━━
7. 结果：清晰目标检测——IoU 0.918

灯条检测集（20 张）：Precision 100%、Recall 100%、平均
   IoU 0.918（绿=人工标注，红=VLM
   预测，几乎重合）。通俗说：该框的一个没漏（召回
   100%），框出来的没有一个是多余的（精确率
   100%），框的位置与人工标注几乎重合（IoU 0.918）。

提示词（测试代理自拟，节选；完整见reproduce/prompts/01_lumino
   us_detect.txt 与 docs/委托测试记录.md）：

  │ You are a precise YOLO annotation
  │    engine. Silently locate EVERY object
  │    instance in the image. Classes
  │    (id=name): 0=LUMINOUS. Then output
  │    ONLY YOLO lines, one per object:
  │    class_id cx cy w h … one TIGHT box
  │    per object … If there are no objects
  │    output exactly: NONE

关键设计有两条：把输出格式钉死为 YOLO 行（每行"类别 中心x 中心y 宽
   高"，直接可训练），并显式要求 TIGHT box（紧贴目标的最小框）、禁止全图大
   框——不写这条，模型倾向给"把整个区域包进去"的偷懒大框。

9. 结果：pose 关键点

主张：pose 输出质量由两个工程要素共同决定——few-shot 示例图钉死输出结构、
   图片尺寸声明钉死坐标系；两者齐备后，像素级精度仍取决于目标大小与清晰度。

关键发现（量化）：提示词中若不声明图片尺寸，模型会自行假设坐标系——同一张能量机关图、同
   一份提示词，补上尺寸声明后框 IoU 从 0.000 →
   0.696。原因很好理解：模型不知道图是 1920×1080 还是 640×480
   时，只能"猜"一个坐标空间，猜错则所有点整体错位。这是本轮最重要的工程发现之一：所
   有坐标类任务都必须在提示词中声明图像尺寸。

好例子（唯一 GOOD）：- 立柱交换站 12 关键点（合成清晰图，few-shot 2
   示例）：12 个红点的结构语义与
   人工标注（黄点）对应良好——顶部角落、边缘、圆环位置齐全。

半好例子（PARTIAL）：- 能量机关 5 关键点（few-shot 2 示例 +
   尺寸声明）：框基本正确（IoU 0.70）、  5
   个点也都落在机构上，但点的定位有可见偏差——结构对了、精度不够，只能算
   "能用来预标注、不能直接当精标"；- 骑马骨骼 12 点（日常照片）：12
   个点挤在骑手躯干附近，没有形成骨骼结构——
   换到与机器人场景差异大的日常图上，结构化输出并不可靠。

坏例子（FAIL，下排）：- 暗光小目标（装甲仅占画面 3%）：即使带 few-shot
   与尺寸声明，红框仍框住  迷彩布——小目标 + 暗光依然是硬边界；-
   背身遮挡人物（厨房）：关键点全部塌缩到画面边缘——无法直接观察的关节
   会被"脑补"失败。

完整提示词（能量机关 few-shot pose，原话；存档于reproduce/pro
   mpts/03_buff_fewshot_pose.txt）：

  │ The first 2 images are ANNOTATED
  │    EXAMPLES: the green box marks the
  │    glowing energy mechanism (BT = blue
  │    target / RT = red target), and the
  │    orange numbered dots are its 5
  │    keypoints: 0 = base of the pole, 1-4
  │    = the circular ends of the 4 blades.
  │    Study the annotation style from the
  │    examples, then annotate the LAST
  │    image exactly the same way: find the
  │    glowing energy mechanism, output its
  │    bounding box and the same 5
  │    keypoints. Respond ONLY with JSON:
  │    {"label": "BT or RT", "bbox":
  │    [x1,y1,x2,y2], "keypoints":
  │    [[x1,y1,v],[x2,y2,v],[x3,y3,v],
  │    [x4,y4,v],[x5,y5,v]]} using integer
  │    pixel coordinates of the last image.

要点解读：前 2 张示例图由脚本自动从人工标注（GT）绘制，few-shot 的示例标注
   不需要人工画；提示词里给每个关键点都写了语义（0=杆的底部，1–4=四个扇叶末端）
   ，不给语义的话模型会把 5 个点全挤到框角上。

   等比缩放校正——这与第 9 节"必须声明图片尺寸"是同一个问题的两面：分割提示词里
   同样应写明图片尺寸，我们后续的运行都加上了。

13. 讨论：实践要点与边界

实践要点（均有实验对照）：1. few-shot
   参考图/示例图是最强杠杆——既提升一致率（68%→98%），又钉死输出结构；2.
   显式约定输出格式（YOLO 行 / JSON schema），并兼容 Qwen
   原生返回   （<points>、<box>、bbox_2d）；3.
   自动对比度增强对暗光数据有效（+2 个百分点）；4.
   自动改档阈值需人工核验标定（本实验为 0.95）；5.
   提示词必须显式排除全部干扰物——语义相似的空间错误（HUD 图标）不会被
   "不要框前哨站"这类部分排除覆盖；6.
   坐标类任务（检测/pose/分割）提示词必须声明图片像素尺寸。

边界（量化）：- 目标 < 画面 5% 时检测/pose 不可用（0 有效匹配）；-
   像素级关键点精度不足（PCK@0.1 = 0%），需专用模型或人工精修；-
   密集场景（数十框/图）召回不足。

15. 结论

贡献：一套可复现的 VLM
   视觉标注评测方法（封闭数据环境、格式规范、独立评测、失败可视化），以及在 22
   套真实 CV 数据集上的量化结论。

决定性证据：复核一致率 99.7%（n=700 稳定复测）、清晰目标检测 IoU
   0.918（P/R 100%）、中文描述与多边形分割的完整输出样例。

意义：Qwen3.8-27B 应部署为 CV 数据管线的质检员、粗标注员与文档员——三个
   角色均已验证；像素级精标与小目标场景保留给专用小模型。

边界：结论限于本文数据分布（RoboMaster 场景 + 日常照片）；提示词敏感性意味
   着每次任务变更都需要一轮提示词校准（本文的配置矩阵方法可直接复用）。
