# 【应用案例】Qwen3.8-27B 视觉标注实测：本地多模态大模型在 CV 数据管线中的三个角色

> 在 RoboMaster 真实 CV 数据集和部分网络图片（1955 张、22 套、6 种标注类型）上，
> 验证 Qwen3.8-27B 可承担 CV 数据管线的三类工作，并给出量化边界。
> 全部代码、提示词与复现脚本开源（reproduce/run_all.sh 一键复现）。

## 1. 核心结论

| # | 结论 | 关键数字 |
|---|---|---|
| 1 | 分类复核可放心交给 VLM，前提是提示词附每类参考图（few-shot） | 一致率 **99.7%**（无参考图仅 93.7%） |
| 2 | 清晰大目标检测预标注接近人工水平 | P/R 均 **100%**，平均 IoU **0.918** |
| 3 | 坐标类任务提示词必须声明图片像素尺寸 | 同图同提示词，框 IoU **0.000 → 0.696** |

一句话避坑版：参考图是最强杠杆；坐标任务必声明尺寸；干扰物必须逐个显式排除；
自动改标阈值需人工核验（本实验 0.95）；小目标（< 画面 5%）与像素级关键点放弃 VLM。

## 2. 系统与工作流

| 项 | 配置 |
|---|---|
| GPU | RTX 4090（24 GB），单卡本地推理，数据不出本机 |
| 引擎 | llama.cpp（CUDA，-ngl 99，65K ctx，q8_0 KV） |
| 模型 | Qwen3.8-27B-UD-Q4_K_XL（GGUF）+ mmproj-F16 视觉头 |
| 服务 | 一键脚本，OpenAI 兼容 API（:8080/v1/chat/completions） |

三个角色实验：**① 质检员**（数据集逐张复核）、**② 粗标注员**（检测/关键点）、
**③ 描述员**（生成中文数据集说明）。各角色独立封闭数据集 + 自动评测脚本，
预测与评测解耦。

## 3. 分类复核：提示词配置决定一致率上限

六组配置对比（每组每类抽样 50 张共 350 张，seed 固定）：

| 配置 | 一致率 | 速度 | 1.4 万张全量 |
|---|---|---|---|
| 仅放大 ×6 | 93.7% | 0.90 s/张 | ≈3.5 h |
| 仅放大 ×3 | 94.3% | 0.89 s/张 | ≈3.5 h |
| ×3 + 自动对比度 | 95.7% | 0.85 s/张 | ≈3.3 h |
| ×6 + few-shot 参考图 | 99.4% | 1.49 s/张 | ≈5.8 h |
| **×6 + 参考图 + 对比度（最优）** | **99.7%** | 1.42 s/张 | ≈5.5 h |
| 最优配置换种子复测（每类 100 张） | 99.0% | 1.42 s/张 | 稳定 ✅ |

**few-shot 参考图是最大杠杆（+3.7 个百分点）**，自动对比度再 +0.3。

核心提示词（完整模板见 core/prompts.py）：

- 系统词：严格单标签分类器，只输出一个 JSON 对象，禁止散文；
- 用户词：类别清单每行 `id i: "类名" -- 文字描述`；
- few-shot：消息附 N 张参考图（顺序与类别清单一致），声明"最后一张是待分类样本"；
- 输出格式钉死：`{"label": "<类名>", "score": <0..1>}`。

## 4. 参考图特异性修复图标类

| 类别 | 基线 | 最优配置 |
|---|---|---|
| 数字类 1–4 | ~100% | ~100% |
| 0 哨兵（图标） | 68% | **98%** |
| 6 前哨（图标） | 92% | **100%** |
| 7 基地（图标） | 与 0 互混 | 混淆清零 |

图标类图案互为镜像 + 暗光拍摄，是唯一瓶颈；注入参考图后混淆几乎清零——
瓶颈是"样例太少"而非"认不出来"。

## 5. 最优配置混淆矩阵近对角 + 自动矫正安全阈值

最优配置 350 张仅 1 张不一致（2→1，人工核验为**数据集真实错标**，VLM 纠正）；
基线错误集中在 0→7（12 张，暗光图标互混）。

55 张分歧样本逐张人工核验的两个事实：

- VLM 抓到真实错标（数字 1 被旧模型标成 2，置信度 1.00）；
- 基线下 VLM 分歧正确率仅 ~5%，盲信会引入新错误。

结论：**置信度 ≥ 0.95 的分歧才自动改档，其余进网页审查队列**——
0.8 会被图标类高置信误判穿透，0.95 由人工核验标定。

## 6. 检测：清晰目标可用，干扰物必须显式排除

| 场景 | 结果 | 教训 |
|---|---|---|
| 灯条检测（20 张，清晰大目标） | P/R 100%，IoU 0.918 | 输出钉死 YOLO 行 + TIGHT box，禁止全图大框 |
| 多车直播截图 | HUD 图标被当机器人框出，真车漏检 | 提示词必须**显式排除全部干扰物**，部分排除会被空间相似目标穿透 |
| 密集场景（数十框/图） | P 17%，召回严重不足 | 不可用 |

## 7. pose 关键点：两个工程要素 + 硬边界

**关键发现**：提示词不声明图片尺寸时模型自行假设坐标系——同一张能量机关图，
补上尺寸声明后框 IoU 从 **0.000 → 0.696**。所有坐标类任务都必须声明图像尺寸。

| 案例 | 结果 |
|---|---|
| 立柱交换站 12 点（清晰合成图 + few-shot） | GOOD：12 点结构与人工标注对应良好 |
| 能量机关 5 点（few-shot + 尺寸声明） | PARTIAL：框 IoU 0.70，点齐但定位有偏差 |
| 骑马骨骼 12 点（日常照片） | PARTIAL：点挤在骑手躯干，未成结构 |
| 暗光小目标（装甲占画面 3%） | FAIL：框住迷彩布 |
| 背身遮挡人物（厨房） | FAIL：关键点塌缩到画面边缘 |

要点：few-shot 示例图由脚本自动从 GT 绘制，无需人工画；每个关键点必须写语义
（如"0=杆底，1–4=扇叶末端"），否则点会挤到框角。

## 8. 图片描述与语义分割

| 任务 | 表现 |
|---|---|
| 中文图片描述（3 张日常图） | 输出"环境/人物/细节"分层说明，可直接作数据集文档初稿 |
| 语义分割（摩托车/人物） | 41 / 114 点多边形，轮廓基本贴合 |

注意：分割坐标尺度不稳定（自拟坐标系），提示词同样应声明图片尺寸，
接收端做自动等比缩放校正。

## 9. 效率账

| 任务 | 单图延迟 | 吞吐 |
|---|---|---|
| 批量分类 | 1.0 s | **174 张/min** |
| 检测（清晰目标） | 1.3–9 s | 19–38 张/min |
| pose（few-shot） | 4.3 s | ~14 张/min |
| 图片描述（中文） | 9–16 s | — |
| 语义分割 | 10–28 s | — |

显存常驻 20.5 GB；**thinking 模式负收益**（慢 3–10 倍，结构化输出解析成功 0/2），
标注任务应关闭。1.4 万张全量复核约 5.5 小时单卡过夜跑完。

## 10. 实践要点与边界清单

实践要点（均有实验对照）：

1. few-shot 参考图是最强杠杆：一致率 68%→98%，同时钉死输出结构；
2. 显式约定输出格式（YOLO 行 / JSON schema），兼容 Qwen 原生返回；
3. 自动对比度增强对暗光数据 +2 个百分点；
4. 自动改档阈值需人工核验标定（本实验 0.95）；
5. 干扰物逐个显式排除（HUD 图标案例）；
6. 坐标类任务必声明图片像素尺寸。

量化边界（不可用场景）：

- 目标 < 画面 5%：检测 / pose 均 0 有效匹配；
- 像素级关键点：PCK@0.1 = 0%，需专用模型或人工精修；
- 密集场景：召回严重不足。

## 11. 结论与复现

Qwen3.8-27B 应部署为 CV 数据管线的**质检员、粗标注员、文档员**（均已验证）；
像素级精标与小目标保留给专用小模型。结论限于本文数据分布；提示词敏感意味着
每次任务变更需一轮提示词校准（本文配置矩阵方法可直接复用）。

```bash
bash reproduce/run_all.sh        # 环境 → 基准 → 数据集 → 复核矩阵 → 评测 → 出图
bash reproduce/06_user_demos.sh  # 检测/pose/描述/分割演示（提示词见 reproduce/prompts/）
```

提示词原文：`reproduce/prompts/`；完整量化报告：`docs/测试报告.md`；
独立测试代理记录：`docs/委托测试记录.md`。
